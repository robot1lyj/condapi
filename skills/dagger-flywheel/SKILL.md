# DAgger 训练飞轮

把首次大数据任务微调得到的模型作为固定训练基线，围绕真实失败采集专家纠正、累计数据、普通监督全量微调并评估。基线不限20小时，数据量、模型族、帧率、动作维度和chunk长度从真实合同读取。

## 进入任务

1. 先识别用户本次要做的是设计、审核数据、实现缺失入口、启动训练、评估还是推进下一轮；只执行当前已授权范围。建立skill/计划不是提交训练或切换线上服务的授权；本轮同一配方已有明确确认则继续，无须重复询问；总体流程授权或上一轮确认不能替代本轮配方确认。
2. 读取项目既有规则和记忆路由，检索当前campaign/round记录。不创建第二份项目记忆，不把运行路径、实时服务状态、结果写进skill源码。
3. 定位固定基线 `M_base`、原训练集 `D_base`、各轮纠正 `C_1..C_r`、当前已验收采集模型 `M_collect`。`M_base`不是官方预训练base，也不是可变latest。基线来源可以是任意规模任务SFT；普通/RTC训练条件分别继承真实合同。
4. 在condapi中按 [项目接入](references/condapi.md) 定位已有工具与owner；其他项目沿用其原生数据/训练器。不要臆造双数据源CLI参数。

## 每轮先确认配方，再写训练配置

用户明确要求：**每轮写训练配置之前，必须先向用户展示本轮具体训练配方并取得明确确认。** 这一步在生成或修改本轮原生训练配置、训练命令和作业文件之前执行，不能先写好配置再询问。

- 确认前可完成数据盘点、审核、划分、有效窗口统计、入口能力核对和预算计算，并形成文字/表格配方草案。轮次计划manifest可以记录草案，但不得把它当可执行训练配置。
- 待确认表至少列出：轮次/候选实验、初始化checkpoint、各数据版本与train/val、混采比例、全量更新范围、batch、步数及各池曝光量、学习率/warmup/调度、RTC/horizon/norm、seed、保存/评估点、资源预算和停止条件。未知关键值先补齐，不能拿模糊范围当已确认最终配方。
- A/B等多个候选可以一次展示并由用户整组确认；确认只覆盖明确列出的候选和配方版本。上一轮或整个campaign的同意，不自动覆盖新一轮。
- 等待明确回复；未回复、超时或默认选项均不是确认。等待时可继续与配方无关的准备，不生成依赖该确认的训练配置。
- 记录确认的配方版本、候选范围和用户回复来源；确认后按原样生成配置。改变数据、比例、初始化、步数、LR等已确认配方内容，要先展示差异重新确认。完全相同合同的中断恢复不算新配方，无须重复确认。
- 配方确认不自动等于立即提交训练或上线；是否执行沿用用户在本轮已经明确授权的范围。这是用户要求的配方确认，不是工具自动审批。

## 不改变的学习定义

- 默认每轮从**同一个固定任务SFT基线**初始化权重，创建新run、优化器和学习率日程。采集用当前最好且已通过验收的模型；两者可以不同。
- 第r轮训练使用 `D_base + C_1 + ... + C_r` 的合格训练部分。历史纠正不因轮次更换而丢弃，任何holdout不进入未来训练。
- DAgger是采集与聚合流程；模型仍使用普通任务指令、观测和专家动作做原生监督全量微调。介入字段用于离线筛选、追溯和采样，不自动成为prompt、模型输入、奖励或额外loss。RTC基线继续使用原RTC目标。
- 沿用现有模型/processor/trainer；不引入第二套训练循环，不把Pi的delta、32D、H50或norm规则套到其他模型。
- 学习率、混采比例、样本数量与预算是候选配方，不能宣称论文保证。固定基线本身未学过各轮C，因此历史C要重新学习，不仅是防遗忘回放。

## 按阶段处理

按需读取 [工作流](references/workflow.md) 的相应阶段，不预加载所有历史：

| 当前工作 | 必须形成的可审查产物 |
|---|---|
| 冻结基线/设计campaign | 固定权重、资产、数据和环境引用；3轮主计划＋最多2轮条件扩展 |
| 接收与审核HIL数据 | 原始清单、字段语义核对、质量/缺口报告、可追溯纠正片段清单 |
| 发布训练集 | 独立版本、分组train/val、有效窗口索引、每池有效样本数 |
| 设计训练 | 先提交配方/预算表并取得本轮确认；再生成原生配置、恢复合同与真实命令，记录缺口 |
| 运行训练 | 经授权计算资源上的job ID、日志、配置、检查点和恢复证据 |
| 评估/交接 | 分池验证、真机对照、晋级/保留/停止理由与下一轮目标 |

[轮次记录模板](assets/round_manifest.json) 可复制到项目既有实验产物目录，填写未知字段；`null`表示未知，不能当0或通过。模板不是训练器配置，不能直接提交；`planned/released`等状态需实际证据支持。

## 完成一轮的规则

- 保存原始完整rollout，另导出连续有效专家数据；不能跨控制权/epoch/缺口拼chunk、不能把缺失占位0当动作。
- 按实际有效窗口数与各池采样比例计算暴露量；相邻chunk重叠不等于独立样本，窗口数不再乘horizon。
- 学习率日程、数据版本和mix在启动前冻结；新数据/比例变化要新run，同run恢复只用自身完整checkpoint。
- 初轮先小规模验收采集链路，再收约50个有效纠正事件；分组隔离优先于精确40/10数量。不故意制造失败凑数。
- 先完成离线准备和检查，再在允许的资源运行；训练合格不等于端侧转换合格，更不等于任务成功。只有在已授权且独立部署验收完成后才切候选服务。
- 常规做3轮复盘；第4、5轮由剩余可恢复错误、明确采集目标、近期收益和用户预算决定。提前达标、低纠正需求或连续两轮无收益可以停止，不机械跑满。

## 回复与记录

每轮说明“已有证据、当前产物、尚缺事项、下一步及其执行边界”。写回项目owner，保留旧证据；不把计划标成已实现，也不以端口监听或低训练loss替代推理/任务验收。

用户仅要求设计时交付具体配方与缺口，不启动训练；用户要求执行时完成已授权的准备、实现、检查和运行，不停留在泛泛建议。
