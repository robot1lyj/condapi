## 本轮究竟采用什么方法

保留已有讨论：冻结Pi0.5，学习整轮双臂小残差；不设抓取阶段门控，不要求快速键盘救场，不做actor模仿预热。**本实验不是PARTS原文的局部TD3+BC复现。** [PARTS](https://arxiv.org/html/2609.21788v2)给我们的参考是有界残差与任务瓶颈思想，以及LEGO整轮进度评分；原文PARTS主体使用局部奖励、分瓶颈TD3+BC。我们此前确定的critic离线初始化→SAC路线依据[PLD](https://arxiv.org/html/2511.00091v1)与[Cal-QL](https://arxiv.org/html/2303.05479v3)，是明确的项目适配。PLD论文的默认初始化用50条成功base rollout，之后仍有在线交互；不能据此声称14集离线训练就能收敛。

这14集记录的是基础Pi动作，没有尝试残差。它们能帮助评估器学习当前表现、进度和失败状态，却没有提供“同一状态向哪个方向修正更好”的直接对照。**只训练critic、actor保持零均值时，确定性推理仍等于Pi；不能发布成已经变强的小专家。** 真正的动作改进需后续有界探索及SAC更新，以真实终点结果检验；不是靠训练loss证明。

9集train的终点合计77/90，3集holdout28/30；这是分层留出的描述，不拿holdout数字当新策略成功率。12集总体105/120。数据量很小，单次留出无法证明泛化。首轮旨在验证学习链路、排除过拟合和观察是否有改进趋势。

在gamma=1时，一条无人轨迹每个历史决策的MC回报均等于其终点C/N，这是“未来累计回报”标签；只有最后一次转移的即时奖励为C/N，中间即时奖励仍为0。这种标签不能告诉网络究竟是哪一次抓放造成了错误，14集尤其容易把摆放难度与动作优劣混淆，因此需要后续真实修正数据。

前1000次MC critic拟合是为长轮次稀疏终点提供较直接的数值初始化，是本项目提案；**不是actor模仿预热，也不是Cal-QL原论文的必选步骤**。只用真实终点/完整无人轨迹得到的回报，不把每帧都标成功1；MC标签只作回报目标，绝不把事后知道的“距真实结束还剩多久”输入actor而泄漏未来。状态中的剩余预算只能由预先规定预算与当下已过时间计算。

## 实现、验收和上线顺序

1. 用户确认上述首轮配方后，在PART分支完成观测/特征缓存、chunk/队列replay、server入口和snapshot绑定。权重/norm/feature/物理合同必须有哈希。现有学习器是14D单步物理action基础，需要显式适配规划残差与RTC队列；没有现成一条命令就能训练的完整入口。
2. 复用实际接受/取消/选择及submitted_action记录，重建每次请求时的prefix与队列；状态转移按真实相邻决策时间。规划残差是入队决策，实际执行和下一队列共同形成环境转移；未执行H50尾部不能当已发生的50步运动。缺prefix或来源则隔离相关决策，不能伪造零队列。
3. 先静态与纯数组检查，再在用户腾出的一张4090上做100次GPU数值/保存恢复校验，计入5000次预算。确认critic变化、actor零均值未变、有限梯度、target更新与恢复一致；测出缓存吞吐/每步耗时后报告剩余预计时间。每1000次检查train/holdout MC误差和TD误差；若连续两次holdout MC误差上升且train下降，则提前停止并保留此前验证最优快照。当前没有实测，不能承诺“几分钟训好”。首次含缓存和GPU验收可先预留1–2小时资源窗口，这是预算估计，不含代码实现、真人复位、采集和端侧验收。
4. 完成离线critic初始化后仍不发布“learned eval actor”。Thor先验零残差与base一致、feature一致、前缀逐值不变、最终动作约束及延迟，再做跨IPC真实smoke。客户端新增记录/协议任务先展示给用户审核，不自动发送，本仓库不修改3588控制代码。
5. 用户认可采集接口后执行5+5集小幅探索与批次SAC更新。每集只标一次最终结果；旧14集不能代替修正后的真实经验。若Pi的错误是语义上选错颜色槽位，小幅关节残差未必能解决；当前pilot更可能先检验放置稳定性，结果不改善就停止扩量，不盲目增大修正。
6. 冻定actor且关闭探索，用10组新初始摆放做Pi-only与Pi+residual交替对照，共20集；两组同20w、相同150秒预算、10块和计数规则，评测数据不回流训练。看平均正确比例、分错数、掉落/未完成数、整集成功率及耗时。平均进度增加≥5个百分点且分错/未完成不恶化作为后续扩量的pilot门槛；这20集不是统计上充分的结论。不达门槛保留Pi-only，分析错误再定下一轮。
