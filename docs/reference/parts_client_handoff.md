## 已确认的目标和参数

| 项目 | 当前决定 |
|---|---|
| 修正对象 | 左、右抓取的下降接近动作；基础策略保持冻结 |
| 介入高度 | 左右初始均为50 mm，内部0.05 m，分别配置并可修改 |
| 下降目标 | h_goal 单独配置，具体值尚未确定 |
| 网络状态 | 图像特征、14D状态、基础动作，以及当前高度、目标高度和误差 |
| 抓取结果 | 关爪后使用新鲜有效的 abs(effort_nm)>0.65 |
| 奖励 | 高度误差辅助分量与抓取结果分量分别记录；公式、权重待确定 |

高度拟统一为末端参考点沿桌面法向、相对桌面的距离。客户端需要报告当前 FK 的参考点、坐标系、单位及桌面转换；50 mm的数值已确认，测量参考尚未现场核对。对同一参考点定义 `error_m = height_m - h_goal_m`，高于目标时为正。h_goal 未设置时误差和高度奖励为null，不填0。

本次客户端执行器沿用14D绝对关节目标：左J1–J6、左夹爪、右J1–J6、右夹爪，关节rad。现有工程候选是活动臂六关节增量，左右索引分别0–5、7–12，候选块50×6；这属于项目工程选择。客户端按握手的动作空间、索引、形状、单位和边界校验，不将某个关节当高度。单维末端高度动作及IK映射属于另一个合同，不能直接塞入本合同。

## 本轮客户端改造：自动规则选择器（待审核的实施方案）

用户要求每次抓取不再人工标记，不调用额外VLM。采用本地确定性规则，自动产生每臂的 `eligible / empty_hand`，再由原尝试状态机处理高度入口、关爪、奖励和交还。规则只裁决资格，不生成机械臂动作。这是针对本项目简单抓取/搬运/放置流程的工程实现，不称论文原作者的具体选择器代码。

### 1. 输入与一次性配置

复用 `controller.observe()` 已收到的14D实际状态、FK、SDK夹爪反馈及 `submitted()` 保存的实际提交目标。当前 `robot/yam_adapter.py:hil_read_with_gripper()` 已提供归一化实测 `position`（0闭、1开）、有符号 `effort_nm`、`sdk_updated_at / sampled_at / feedback_age_s / valid`；不新增CAN读取或模型调用。

左右分别配置下列项目；除已有50 mm和0.65阈值外，不擅自填写现场数值：

| 配置 | 作用 |
|---|---|
| `selector.schema = rules_auto_v1` | 本次拟实施规则的版本；记录配置哈希 |
| 每臂 `grasp_xy_polygon_m` | 桌面坐标系中的抓取区白名单；用一次性标定的XY多边形排除各放置区；校验有限点、非退化、无自交及绑定frame/calibration_id |
| 每臂 `open_position_min`、`open_confirm_s` | 实测夹爪充分张开阈值与持续确认时间；阈值范围(0,1]，确认时间有限且>0，不以张开指令代替实际张开 |
| 每臂 `h_entry_m = 0.05` | 下降介入高度；沿用桌面法向、原FK参考点及m单位 |
| 每臂 `entry_hysteresis_m / minimum_descent_m_s` | 入口抗抖与下降判定；复用现有配置 |
| `confirm_s / max_confirmation_gap_s / max_feedback_age_s / max_pose_age_s` | 力矩及张开确认、新鲜度检查；复用合同，重复SDK样本不延长确认窗口 |

抓取区边界用于排除“未抓到物体但基础策略仍走到放置区下降”等情况。边界必须覆盖本任务全部允许抓取位置；没有匹配标定的边界时，shadow显示资格缺口，collect/eval拒绝启用。配置是一次性场景参数，不是每次抓取的人工标记。场景中抓取区和放置区若重叠，须先用已记录的搬运/释放状态回放证明可区分，不能把同一XY区域冒充已完成空间排除。

`height.py` 同时提供 `table_position_m` 与 `table_frame`，用于区域判断。现有 `position / pose_frame` 是机械臂base系，不能直接同桌面系多边形比较。位置、夹爪、力矩均保留原值、时间与有效性；无效不填0。

### 2. 每臂自动资格状态

新增独立的资格选择器，至少维护以下状态；它不是新增神经网络输入的phase枚举：

| 选择器状态 | 进入/离开依据 | 是否可启动RL |
|---|---|---|
| `UNKNOWN` | 启动、epoch/控制会话切换、反馈中断后；尚未看到有效的张开和回撤证据 | 否 |
| `EMPTY_READY` | 新鲜实测位置持续满足张开要求，末端在入口上方；无持物或待释放锁定 | 仅在抓取区内下降跨越入口时 |
| `HOLDING` | 已发生关爪，推进的新鲜力矩持续严格 `abs(effort_nm)>0.65`；覆盖RL外的基础策略抓取 | 否，搬运/放置低于50 mm也不进入 |
| `RELEASE_WAIT` | 已提交重新张开目标，但尚未得到实测张开确认 | 否 |
| `REARM_WAIT` | 已确认张开，等待回撤到入口上方和旧尝试/残差承诺结束 | 否，满足后回EMPTY_READY |

活动尝试期间由原 `ACTIVE_DESCENT / ACTIVE_CLOSURE / EXIT_PENDING` 管理执行，自动资格不能另起第二个attempt。成功、失败后沿用 `WAIT_REARM`；选择器的持物/释放锁定与尝试生命周期分别保存。左右选择器各自更新，保留全局单活动臂及轮换仲裁。

持物监控从每次已提交的关爪目标开始，在没有活动RL尝试时也运行。采用现有累计闭合识别和推进样本持续力矩规则；成功锁定不等于给RL奖励，只有原attempt在实际交还边界验证成功才产生一次抓取奖励。闭爪启动、手上已有物体、没有观察到关爪历史时保持UNKNOWN，不能默认空手，也不自动发送张开动作。

力矩暂时降到0.65以下不能自动清除HOLDING。保持锁定并记录 `post_grasp_loss` 候选；必须看到本次重新张开目标及随后持续实测张开，才确认释放。该状态仅代表规则确认过的抓取历史，不额外声称已经完成整任务放置。

暂停/人工接管/epoch切换取消活动attempt并清除入口武装和连续确认窗口；恢复后重新同步UNKNOWN。旧标记、旧力矩或旧张开指令不能恢复资格。新鲜张开且回到入口上方的证据能自动恢复，不要求点击抓取按钮。

### 3. 进入与重新准备规则

`eligible` 自动由READY、EMPTY_READY、新鲜位姿/夹爪反馈、抓取区命中及无旧残差承诺共同决定，来源为 `rules_auto_v1`；`empty_hand` 是选择器的自动结论，不是 `abs(effort_nm)<=0.65` 的反值。

入口先在有效高度 `> h_entry_m + entry_hysteresis_m` 时记住 `entry_armed=true`，然后在连续有效下降中跨越 `h_entry_m` 启动。不要要求“紧邻上一帧仍高于入口+抗抖带”，否则缓慢下降经过抗抖带会漏掉合法入口。缺帧/过旧反馈、离开抓取区、提前闭爪、取消/新epoch会清除武装；启动时已经在阈值下方仍记录entry_missed，等待回撤后再武装。

```text
enter_rl = 原attempt处于READY
           && selector_state == EMPTY_READY
           && 抓取区内 && 反馈新鲜有效 && 实测夹爪保持张开
           && 已在入口上方武装 && 正在下降跨越50 mm
           && 无其他活动臂 && 无旧残差承诺
```

成功后的搬运、放置以及放置后尚未回撤的低位区间均禁止重入。失败后也需本次新的张开证据、回撤和旧attempt/承诺结束，不能用尝试开始前的张开样本重复准备。持续失败关爪不产生多个attempt。已有尝试的高度目标、超时、最低高度、成功持续确认、取消与RTC连续交还沿用原合同。

先更新自动资格，再执行该tick的入口判定；随后实际提交命令由 `submitted()` 更新下一tick可用的动作历史，保持before_command反馈只解释此前命令。若活动尝试离开允许修正的抓取区，停止采用新残差，记录取消原因并按已有控制生命周期处理；不对已承诺目标突然清零。

### 5. 协议、记录与采集

保留 `yam-parts-v1` 的原五个 `phase` 值和网络状态维度；新增独立的 `selector_state / selector_schema / selector_config_sha / reason_codes / entry_armed` 诊断，透传每臂请求和逐tick记录。自动规则配置必须纳入锁定的行为合同/manifest并生成新的contract_sha，不能只改客户端JSON却继续冒用旧合同。服务端下一步依据已审核的配置生成匹配manifest，验证附加字段；本计划不宣称这些字段已经实现。

`run.json` 保存规则版本、完整配置/哈希和标定身份。`events.jsonl` 保存同步、资格变化、关爪、持物锁定、释放确认、回撤/重新准备、entry_missed及竞争结果；事件显式带所属臂、tick和SDK证据引用。逐tick保留两臂状态与未启用理由，无活动attempt也记录；这样可以复核放置是否被误识别为抓取。

录制仍在下降到50 mm之前开始，覆盖抓取、搬运、放置、释放和再次抓取。自动规则只替代人工门控，RL数据仍由自主collect真实尝试产生；成功与失败均保留，人工接管/反馈故障取消不伪造成失败。先用已录episode或离线mock验规则，再shadow核对边界，双方条件满足后collect；不在改规则时直接开始真机探索。

### 6. 离线验收与交付

验收覆盖完整序列而非只调用单个条件：

- 不调用mark即可从有效张开、高位接近启动左/右抓取；逐步通过抗抖带的慢下降也能进入，阈值抖动只触发一次。
- 成功后持物下降到50 mm以下、力矩短暂回落、放置张开但尚未回撤均不重入；实测释放+回撤后下一次抓取能自动启动。
- 未成功而基础策略走到放置区下降、空手在放置区下降均无RL；空间判定统一桌面坐标，base系位置不能误当table系。
- 张开指令已提交但实际仍闭合不重新准备；重复/过旧SDK样本不延长张开或力矩确认；位置字段缺失不推断空手。
- 启动低位、启动闭爪/持物、中途启动、暂停恢复、epoch切换、资格丢失、抓取失败重新张开/回撤符合上述规则。
- 左臂持物不阻止右臂正确准备；双臂同tick竞争只采用一臂；未选中臂不伪造attempt。全局RL外的基础策略抓取也能锁定持物。
- shadow最终动作与原基础路径逐值相同；collect/eval只编辑未承诺的活动臂六关节；交还、一次成功奖励和取消规则回归通过。
- 发布样例包含选择器事件、两臂未满足原因、完整抓取→放置→再次抓取序列；从记录能重放并复算资格决定，不能只交按钮截图。

客户端交付提交SHA、修改文件、配置缺口、离线检查结果和新目录中的mock/shadow原始样例包。控制程序不依赖VLM或每次人工标记；规则参数与区域标定仍需一次性现场配置。这是待用户审核的客户端指令文本，本文不自动发送或操作客户端。

## 客户端构建任务

### 配置和高度观测

实现独立的 PARTS 配置结构，模式包括off、shadow、collect、eval，初始off。左右分别包含 `h_entry_m=0.05`、可空 `h_goal_m`、接近资格输入、最低高度边界、下降抗抖规则和时间预算。残差边界、探索配置、力矩确认时间与反馈年龄、奖励公式/权重均从已版本化合同读取，当前未知值保持未设置。

将已存在的FK接入反馈快照，保存末端位姿、参考frame、采样时间、有效性与标定版本。若使用桌面高度，计算 `height_m = dot(n, p_ref - p_table)`，其中n为向上单位法向，所有位置必须先转到同一frame。记录实际反馈高度和基础目标高度，二者分别标识；目标已经下降不代表机械臂已经到达。

提供每臂 `eligible` 接近资格输入。本轮按上节自动规则替代当前人工标记：实测张开/关爪历史、持续力矩、抓取区与回撤决定资格；高度本身不能区分抓取下降、放置下降和持物经过。此前“缺少自动能力时提供显式标记”是首版临时实现，已被用户要求的自动方案取代，不再作为新实现的必经操作。

配置在HOLD且没有活动录制时应用；每次attempt锁定参数和contract版本。调整值另开run并保留旧记录。h_goal、坐标转换或奖励配置缺失时可以做观测记录，但不能声称已经产出完整可训练的RL奖励。

### 介入和退出状态机

每臂实现 `READY → ACTIVE_DESCENT → ACTIVE_CLOSURE → EXIT_PENDING → WAIT_REARM → READY`，同一tick最多一个活动臂。两臂同时满足进入条件时采用明确且可记录的优先级，未选中臂继续基础动作。

READY状态只有在eligible、空手接近、有效高度正在下降并跨越h_entry时进入。默认阈值0.05 m；连续有效高度从大于阈值到小于等于阈值是候选进入规则。启动时已低于阈值的情况先记录 `entry_missed`，等待下一次明确重置/重新接近，不能凭单帧低高度伪造跨越。抗抖、速度和工作区参数须在配置中显式记录。

进入时生成attempt_id并记录entry_tick；首次真正应用残差另记first_residual_tick。关爪开始进入ACTIVE_CLOSURE，下降与关爪属于同一次尝试。没有及时可用候选时记录残差实际延迟，不改写已提交或已承诺目标。

关爪后用原始有符号SDK反馈取绝对值，阈值为严格大于0.65。只使用有效、新鲜且SDK更新时间推进的样本。现有离线分析的“整个闭合过程最大值达到阈值”不能直接冒充在线持续确认；确认时间和最大反馈年龄0.1 s均仍为候选值，需在本轮配置明确。客户端实现可配置判定并保留全部原值，不静默加入速度或空夹位置条件。

成功确认后进入EXIT_PENDING，停止新的探索并请求基础策略依据实际状态及最终RTC前缀生成交还计划。检查关节连续性；旧承诺仍按原来源执行。在实际交还边界再次确认力矩成功，产生一次grasp_reward=1并终止。失败重新张开、时间预算或最低高度边界终止时grasp_reward=0。故障、断联、人工接管、反馈失效和epoch切换记录canceled与null奖励，取消默认不入自主RL训练。

WAIT_REARM需新的实测张开/释放确认、回撤到入口上方、旧attempt及残差承诺结束后才能重新进入，持续关爪不能生成多个attempt。达到h_goal只记录几何目标事件；本版本继续等待关爪结果，不因到达高度就退出。

### 协议透传和执行来源

贯通普通/RTC请求、进程IPC、PolicyWorker Reply、动作选择和录制details中的parts字段。现有ProcessPolicyClient转发原响应，PolicyWorker会丢失新增字段，需要在最终动作链保留关联。普通off继续兼容旧扁平obs；RTC保持原type=infer、obs、rtc结构。

按 [05消息规范](../05_inference_and_rollout.md#parts-消息字段规范) 实现 `yam-parts-v1`。shadow允许旧服务缺少parts能力并记录unsupported；collect/eval要求握手匹配合同、shape、单位、索引与snapshot。不得仅凭端口或收到actions就认定PARTS可用。错误回复、错epoch/obs/request/contract和迟到候选不应用。

残差只加到活动臂尚未承诺的关节目标，保持另一臂和两只夹爪的基础路径。对组合后的最终目标重新执行有限性、硬限位、关节连续性及高度边界检查，保存候选、实际应用差和约束标记。模式shadow的实际应用残差严格为0；eval关闭探索；collect使用Thor一次生成并记录的候选，不在重选同一个target_tick时重新抽噪声。

RTC前d行保持原承诺值和原request来源；只编辑后缀，然后将最终目标承诺进RtcTimeline。下一请求传回最终承诺前缀。不能用新的request给旧前缀重新署名，不能在退出时突然清零关节offset。HOLD/人工介入/故障按既有生命周期清时间轴并取消attempt；RTC继续不叠加TDA或普通夹爪实验变换。

### 奖励和录制构建

客户端产出高度、目标、误差、grasp_reward及奖励事件，按双方固定的reward schema计算height_reward和total_reward。具体公式/权重当前未定，先实现可版本化的接口和原始误差记录，未定分量写null。奖励配置和h_goal缺失时禁止将发布包标为可训练；保留观测数据用于标定和审查。

录制使用原有单一录制器和三路视频，扩展HDF5 details.parts与episode manifest的RL来源引用。额外请求数组、请求索引、事件和attempt表由后台写入；控制线程只入有界队列。记录队列溢出/写失败必须可见并使相应区间不可训练，不能丢失后仍发布完整数据。

复用SDK已有快照读取力矩，不新增CAN轮询。before_command反馈关联上一条已提交命令，不直接标为当前行新命令的后果。保持原始tick、epoch和时钟域，沿用原有视频索引与等待切点标记；轨迹有缺口不拼成连续transition。

### 发布和采集面板

复用现有采集面板，展示PARTS模式、活动臂/阶段、当前高度、h_entry、h_goal、力矩绝对值、反馈有效性及attempt结果。未知值显示未设置，shadow清楚显示正在执行基础动作。模型身份留在交接manifest/sidecar，产品流程无需要求操作员逐帧录入checkpoint名称。

实现持久outbox：episode与请求文件收尾后生成发布清单，后台按双方既有传输方式上传到新目录，幂等重试并保存ack。Pi单在途socket与30Hz提交路径不等待上传或learner；训练server故障不改变当前执行snapshot。客户端只报告文件完整与client_complete，condapi审核后才生成训练READY。

## 数据包和格式

原始记录继续使用yam_hil_v2，不在客户端直接转换LeRobot专家数据。新增RL层为 `yam_parts_raw_v1`；[04发布格式](../04_data_contracts.md#parts-原始发布格式)定义具体物理布局、列和有效性。

成功、失败、取消、人工重置和基线/shadow/eval都留在原始库。condapi在新目录派生train/val与transition，保留原始来源及哈希；客户端不给取消尝试伪造0奖励，不将measured_state当动作，不从动作差猜未知残差。mock、eval与holdout组不进入online训练池。

## 客户端交付和验收

- 一次成功只给一次抓取结果奖励；失败与取消不同；before_command反馈关联正确，缺口不拼transition。
