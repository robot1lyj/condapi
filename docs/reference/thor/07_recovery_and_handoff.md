# Thor 07 · 故障停止、恢复边界与交接

本页供 [00](00_start_here.md) 任一阶段发生异常时使用。先保留现场、停止新增写入；若写入正在进行，“停止操作”是不要再干预，不是拔电终止正在进行的写入。

## 故障分流

| 现象 | 先保存/检查 | 不能做的事 | 下一步 |
|---|---|---|---|
| USB/目标 NVMe 身份不确定 | 磁盘列表、实物、Etcher/安装菜单 | 猜盘符、按回车试探 | 回 G0，确认唯一目标与备份 |
| ISO 长度/哈希不符 | 官方入口、文件名、下载状态 | 改校验记录、覆盖旧文件 | 新目录重新取得并核验 |
| Etcher 校验失败 | 完整错误、软件版本、USB 身份 | 跳过校验、继续刷 Thor | 确认未在写盘后更换已授权 USB/端口，重走 G1 |
| 无 USB 启动项 | 写盘结果、UEFI 版本、启动菜单 | 格式化 NVMe、清所有 UEFI 设置 | 核对启动盘/端口/兼容性 |
| 屏幕黑/看似停住 | 何时变黑、是否正在写固件、屏幕照片 | 用计时器强制断电 | 判断显示问题还是更新中；不确定即求助 |
| QSPI 更新异常/中断 | 更新阶段、完整提示、UEFI 是否还能进入 | 连续重启、刷随机旧版本 | 官方/厂商支持确认恢复流程，另行授权 |
| NVMe 安装失败 | 原始错误、目标身份、空间/供电线索 | 连续重刷、改分区碰运气 | 保存现场，确认写入已停止后查存储/BSP |
| 又回安装菜单 | 上轮完成记录、USB 是否仍插着 | 再选 Install | 确认安装已完成后移除安装介质，选择正确启动项 |
| 系统启动但 GPU 不可用 | G3 输出与本次启动日志 | 装桌面显卡驱动覆盖、重装碰碰运气 | 定位版本/固件/驱动，停在 G3 |
| 宿主 GPU 可用、容器不可用 | image digest/ARM64、runtime、退出日志 | `--privileged` 掩盖问题、删 Docker 数据 | 按 G4 分层诊断 |
| JAX 回退 CPU/加载 LoRA 失败 | 锁文件、后端、checkpoint 元数据、错误 | 删 LoRA、忽略 keys、直接换量化模型 | 停在 G5，交工程 agent |
| 改网络后管理连接断开 | 修改前配置、网卡身份、路由 | 操作 3588、清所有网卡配置 | 用户在 Thor 本地恢复此次变更 |

## 官方恢复入口与适用限制

- [UEFI/ISO 矩阵](https://docs.nvidia.com/jetson/agx-thor-devkit/user-guide/latest/twa_uefi_iso_compatibility.html)：先核对，不能认为刷旧 ISO 能回退固件。
- [重装 USB/显示交接问题](https://docs.nvidia.com/jetson/agx-thor-devkit/user-guide/latest/twa_display_handoff.html)：只对明确匹配的现象/版本使用，不预先应用旧补丁。当前版本的 OOBE 显示挂起分支与旧版所需设置有区别，按对应说明选用，不能混用。
- [BSP 安装替代方式](https://docs.nvidia.com/jetson/agx-thor-devkit/user-guide/latest/setup_bsp.html)：SDK Manager 或 Flash script 是另一条需重新审查的刷写路径，不是 USB 失败后的自动下一条命令。
- [r39.2.1 Thor Flashing Support](https://docs.nvidia.com/jetson/archives/r39.2.1/DeveloperGuide/SD/FlashingSupportJetsonThor.html)：需 Ubuntu 主机、正确恢复接口、匹配板级配置/存储参数。必须先取得实际板号、恢复模式识别结果、BSP 版本、备份和用户对写入范围的确认。这里故意不提供未知硬件的 force-flash/分区命令。

QSPI 更新中断、无法进入 UEFI、硬件/载板身份不清时，不能承诺不丢数据恢复。向 NVIDIA 或整机厂商提供脱敏日志和现象，在明确恢复方法前暂停。

容器层回退仅切回上个已验收镜像/模型/配置，不删除当前资产；运行时配置回退只恢复这次变更的备份并核对差异，重启前确认不会影响其他容器。系统级重装是再次破坏性写入，必须重新走 G0–G2；不是“重试”就免确认。

## 安装记录模板

这是空白模板，不是已发生的证据。每阶段复制到用户指定的私有安装记录/日志位置；若需入库，先脱敏并经用户同意，最终状态回写 [08](../../08_thor_edge_deployment.md#7-当前状态)，不另建平行记忆系统。

```text
记录时间/时区：
手册 Git commit / 执行 agent：
阶段：G0 / G1 / G2 / G3 / G4 / G5
执行位置：制盘电脑 / Thor 宿主 / 某容器
设备整机/模块/载板：
当前 UEFI / 目标 ISO 版本：
USB 身份 / NVMe 身份（私有保存，分享时脱敏）：
备份位置及验证方法（无凭据）：
ISO 官方入口 / 实际下载链接 / 文件名 / 字节数 / SHA-256：
发布者 checksum/signature：已核对及依据 / 未取得及风险知悉
破坏性操作：无 / USB / QSPI / NVMe
用户当场确认的目标、范围及时间：
实际操作或逐条命令：
退出码 / 完成提示 / 脱敏日志和照片位置：
实际通过条件与观测：
未通过项/未知项：
当前是否仍在写固件或磁盘：
允许的下一步 / 必须停止的原因：
变更备份与回退方法：
```

G4 加记：宿主 GPU/驱动、Docker/Toolkit/Compose 版本，测试镜像架构/digest、GPU 运算输出。G5 加记：代码/依赖锁、原 checkpoint/LoRA/norm 摘要、实际 dtype、golden/噪声和比较报告、模型配置、端口/IP、往返延迟/内存，以及对端测试由谁执行；不要用“已完成”替代具体证据。

## 交接的最小内容

交给下一位 agent：当前 G 阶段、设备/目标身份、已确认的写入范围、最近实际输出、未解决风险、是否仍在写入、下一条允许操作。未有结果一律写“未执行/未知”，不给成功截图示例代替现场结果。安装结束留存可读备份和已验收镜像，不自动清理 ISO、原始模型、日志或下载任务。
