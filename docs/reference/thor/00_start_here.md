## 正常安装：只看这条主线

1. 在制盘电脑安装 Etcher，使用已经下载好的官方 ISO，准备一只至少 16 GB、允许清空的 U 盘。
2. Etcher 选 ISO → 选对 U 盘 → Flash，等自带校验完成。
3. Thor 接显示器、键盘和原装电源，从 U 盘启动；需要 QSPI 更新时按提示确认并等待完成，不中途断电。
4. 确认 Thor 的目标 NVMe 可以重装，选 Install on NVMe。完成后拔安装 U 盘，完成 Ubuntu 首次设置。
5. 看系统版本、启动盘和 GPU 是否正常；Docker 能做一次 GPU 运算，即完成基础环境安装。
6. 再构建 Pi 系列容器，先跑原 JAX checkpoint；模型精度和性能在这一阶段处理，不挡前面的系统安装。

第一次确认整机是否为官方开发套件即可；第三方载板才走厂商流程。无异常无需读完下面所有详细文件。阶段编号只是定位进度，不要求逐项签字、重复截图或填写全套表格。

## 给指导 agent 的执行规则

### 当前采用：简洁指导模式

2026-09-07 用户选择由当前 agent 直接指导，并要求避免过度验证。正常路径按以下节奏推进，详细章节留作遇到问题时的冷参考：

- 先准备 Etcher 与现有 ISO，再确认设备适用和两次磁盘写入目标；已有可信记录不反复索要截图/重算哈希，同一 ISO 未变化无需每阶段重验。复制到新电脑或出现错误时再查。
- 必要检查保留：USB/NVMe 不能选错、重要数据有备份、固件更新不断电、安装后系统版本/启动盘正常、一次容器真实 GPU 运算。
- 正常步骤可连续指导，不要求每条只读命令都单独回复；到破坏性写入或出现异常时才停下确认。
- 记录简短结果和必要错误即可，不把填写完整模板作为正常安装的前置条件。G3 的扩展日志排查和重启复核按异常/需求执行。
- 安装系统不等待模型逐层精度研究。G4 后再处理 JAX/Pi；格式转换或量化时仍需精度对照，不能用“加快安装”代替模型可靠性判断。

1. 遵守仓库 `AGENTS.md`，只负责 Thor。3588 的控制、相机和系统均不读取、不修改、不登录。网线直连的对端测试由用户/控制侧负责人配合。
2. 每轮围绕当前检查点：说明在哪台设备做、是否写入、预期现象和失败停止条件；可合并相关只读检查，不一次下发跨多个破坏性阶段的动作。
3. 写 U 盘前和安装 NVMe 前确认具体目标可覆盖；空盘/新机只需用户确认没有要保留的数据。固件更新按安装器提示确认即可，不额外增加一轮审批。
4. 任何设备名、网卡、IP、用户名、镜像 digest 均取现场值。占位符不是可执行配置；不得把自己电脑的磁盘当成用户 Thor 的磁盘。
5. 显示内容与手册不同、版本不匹配、出现未知安全启动/加密要求、目标不唯一时暂停。不要为了继续而关闭 Secure Boot、清 TPM、烧 fuse 或恢复所有 UEFI 默认值。
6. 版本选择和精度决策的唯一 owner 是 [08](../../08_thor_edge_deployment.md)；本组只持有逐步操作、风险与检查点。发现官网变化先记录差异，不悄悄换系统或降精度。
7. 含系统配置修改的代码块只在对应前置条件通过后由指导 agent 单独下发。本次文档任务没有授权实际执行其中的写入。
