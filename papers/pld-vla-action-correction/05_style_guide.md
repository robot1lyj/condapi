# 写作与引用规范

- 中文内部研究材料，保留原论文方法名与公式。类型为 algorithmic 研究计划，期刊格式暂不限定。
- 基于用户已有方向组织研究问题；候选机制由研究者进一步讨论与选择，不能把模型建议当已确立创新。
- 用“已报告”“历史审计记录”“拟检验”区分证据；不用“显著提升”“首次”“全面领先”替代实验。
- 引文就近给原论文 URL，BibTeX 只记录核实字段。读取摘要与读取方法章节分开记录；不以机构名望替代方法证据。
- 方法名称统一到 `01_research_canon.md` 术语表，不另造方法缩写。
- 成功指标总写清分母：有效局部候选、所有实际尝试、完整 rollout 三者分开。
- 图注明确“拟议架构”与“历史数据审计”；未来实验图只列规划，不填模拟结果。
- 用户于 2026-10-13 明确偏好：论文 HTML 与技术图由本对话独立设计，不使用 Archify；用同一视觉风格结合交互演示与固定实验来源。
- 用户于 2026-10-13 确认采用“发布会原则”：围绕最强且有证据的优势组织正文；摘要/引言按问题→缺口→思路→最硬结果展开；每项实验承担明确论证职责，结论强化同一记忆点。提交过程与失败命令保留在实验档案。
- 将反复的“不能证明”“不是”“不保证”改为机制定义、实验条件和指标范围。实际不利结果、必要条件和样本构成保留；比较指标在评价前按研究目标确定，避免因结果选择口径。未完成的结果用明确占位。
- 最新论文层次：RTC 为已有技术，实时 VLA 强化学习也有直接先例；RTC＋RL 的具体衔接是第一部分的小亮点。后续 RL 及架构实验继续形成核心贡献，当前系统证据与策略结果分别呈现。
- 技能使用：researchwrite 的事实/证据/论证底稿、nature-academic-search 的原始来源核查、nature-writing 的算法论文论证顺序、nature-statistics 的独立单位与统计边界。
