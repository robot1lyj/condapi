# 先例与候选想法审计

这不是创新点清单。用户明确当前以文献调研、逐步确定想法和实验推进为主。下表用于以后避免重复发明；不要求现在选定方法名或论文卖点。

## 2. 可以先观察的现象

**方向 A：自动奖励误差到底怎样影响 residual 学习。** 不只测分类准确率，而是分开研究语义误报、跨尝试错配和执行记录错配。固定算法/编码器，在真实连续 rollout 上判断它们是否足以解释学习退化。可能形成有价值的实证研究，即使没有新优化器。

**方向 B：存在真实歧义时如何学价值。** 前提是正确时间戳、attempt ID 和强视觉模型仍不能解决结果归属。候选方法可以显式表达多个可能归属，而非硬贴标签；只有目标函数、假设及公平对照清晰后才谈算法创新。标准 masking、限幅或队列字段只是必要工程。

**方向 C：同一学习接口跨任务是否减少适配成本。** 把奖励器、残差、入口/退出协议拆开，测换任务时需多少数据、人工审核和专用规则。它可能是系统贡献；仅提供“通用接口”但每个任务重写整条链路，不支持泛化结论。

三者不必同时做。先观察哪一种问题在新 rollout 中真实、频繁并影响收益，再决定论文主问题。

## 3. 不成立时怎么办

| 观察结果 | 合理结论 |
|---|---|
| 简单正确索引已解决所有错误 | 形成复现/工程结果，不将修 bug 包装为算法。 |
| 局部奖励更准确但完整任务不改善 | 结果测量改善成立，策略收益不成立；检查探索、动作范围和交接。 |
| 只在 LEGO 上有效 | 任务研究或系统适配，不能称跨任务方法。 |
| 收益来自额外数据/更大模型 | 归因到资源或表示，不归因到候选机制。 |
| 冻结专家有效，蒸馏后无改善 | 外挂路线成立，长期能力吸收尚未成立。 |

当前结论：有值得研究的问题，尚未确认独立算法创新。这个状态符合项目所处阶段，不阻止合理复现和实验。
