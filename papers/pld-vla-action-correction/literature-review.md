# VLA 强化学习文献调研：共同骨架、实质差异与 PLD 路线

版本 0.1 · 2026-10-12 · 中文工作底稿。本文按机制整理原论文；不是跨论文成绩排行榜，也不是穷尽检索的系统综述。来源、读取深度和版本见 [文献登记](sources/literature.md)。

## 1. “本质差不多”在哪个层面成立

大量工作共享同一个闭环：有能力的行为先验 → 机器人尝试 → 结果反馈 → 估计行为价值 → 改进策略 → 再次尝试。预训练模型缩小搜索范围，RL 利用成功和失败的差异改善行为。这一骨架并非每篇新论文重新发明。

但下面六个选择会改变算法、样本需求与部署方式，不能全归结为换场景。

| 维度 | 需要问的问题 | 对我们有什么实际影响 |
|---|---|---|
| 学习对象 | 更新 VLA、动作残差、噪声策略，还是表示上的新动作头？ | 决定算力、表达能力及原能力是否受影响。 |
| 探索空间 | 在关节/末端动作中试，还是在生成器可产生的轨迹中选？ | 决定能否补出底座很少产生的修正。 |
| 价值时间尺度 | 一个控制步、一个 chunk、一个局部尝试还是完整任务？ | 决定反馈稀疏性、闭环反应与 off-policy 备份方式。 |
| 奖励来源 | 人工成败、视觉判别器、VLM、状态规则或轨迹偏好？ | 决定自动化、误报代价与跨任务适配成本。 |
| 数据机制 | 自主 rollout、成功回放、人工纠正、局部重试还是仿真？ | 决定学习分布与真实机器人时间成本。 |
| 能力存放位置 | 留在外挂专家，还是回到 VLA 权重？ | 决定部署复杂度与“长期保留”是否真的完成。 |

“都用 SAC”不代表同一种方法，因为 SAC 可以优化关节残差，也可以优化生成器的初始噪声。“都用监督损失”也不代表相同数据来源：普通 BC、RL 专家蒸馏和 advantage-conditioned 学习的信号不同。

## 2. 用六个最小表达式读懂方法家族

下表是帮助比较的简化表达式，不替代原论文完整目标，也不意味着这些表达式互相等价。

| 家族 | 简化形式 | 代表 | 主要权衡 |
|---|---|---|---|
| 直接更新动作生成器 | `a ~ πθ(o,g)`，用 RL 更新 θ | [VLA-RL](https://arxiv.org/html/2505.18719v1)、[ReinFlow](https://arxiv.org/html/2505.22094v1) | 能改变策略本身；大模型优化、探索和回放更昂贵。ReinFlow 还需处理 flow 概率计算。 |
| 动作空间残差 | `a = πb(o,g) + δθ(o,ab,g)` | [PLD](https://arxiv.org/html/2511.00091v1)、[PARTS](https://arxiv.org/html/2609.21788v2)、[ResiP](https://arxiv.org/abs/2407.16677) | 学习模块小，易限制修正范围；残差界限与局部观测可能限制行为。 |
| 噪声空间 steering | `w ~ μθ(o,g); a = F_b(o,g,w)` | [DSRL](https://arxiv.org/html/2506.15799v2) | 不更新底座且可黑盒访问；行为受生成器的可达输出约束。 |
| 表示接口上的动作学习 | `z = f_b(o,g); A ~ μθ(z,p,Aref)` | [RLT](https://arxiv.org/html/2604.23073v2) | 利用 VLA 表示、小 actor/critic；需先得到合适 RL token，并非普通外置图像编码器。 |
| 联合编辑与底座更新 | base proposals → Q/edit selection → 成功经验更新 VLA | [EXPO-FT](https://arxiv.org/html/2605.25477v2)、[Real-Time EXPO-FT](https://arxiv.org/html/2609.18207v1) | 专家与底座在统一闭环中进化；在线大模型更新和候选选择增加系统复杂度。 |
| 优势条件化后训练 | 从回报/价值构造 improvement 条件，学习 `πθ(a|o,g,I)` | [RECAP](https://arxiv.org/html/2511.14759v1) | 便于吸收异质经验与 flow 动作头；需要可信价值和覆盖，不能等同于只筛成功数据。 |

这些家族可以组合。PLD 的蒸馏阶段会更新 VLA；RLT actor 也会围绕参考动作编辑。分类依据是各方法关键学习接口，不是说它们完全互斥。

## 3. 对我们最重要的原文差异

### 3.1 PLD：小专家是手段，分布对齐采集与蒸馏是完整闭环

PLD 不是只挂一个 residual。原文 §3.1 用成功的底座 rollout、Cal-QL 初始化及离线/在线混合回放启动专家；§3.2 让底座先运行，再由专家接管，以采集接近底座部署分布的恢复经验，最后 SFT。只学到很窄的专家成功轨迹，未必最适合反哺 generalist。[PLD 原文](https://arxiv.org/html/2511.00091v1)

对我们的启示是把“专家有效”和“VLA 独立变好”分开验收。现有 Pi-only 轨迹可用于有限支持下的初始化，但不自动满足原文成功轨迹配方；局部标签、完整成功及非零残差覆盖要分别检查。

### 3.2 PARTS：把机器人时间集中到瓶颈

PARTS 保留冻结底座，选择局部瓶颈反复实践，采用 selector/verifier、局部结果奖励和 chunk TD3+BC。LEGO 附录实例只改夹爪，但通用 mask 并不限于夹爪；局部成功后交回底座也已存在。[PARTS §III、附录 D](https://arxiv.org/html/2609.21788v2)

我们的“整个抓取阶段都可改”是相对该 LEGO 配置的扩展，不是对整个 PARTS 方法家族的新定义。它是否值得，需要与仅开度修正按同预算比较。

### 3.3 RLT：关键是表示，不是人一定要及时按暂停

RLT 把底座内部表示压成小专家可用的 token；actor 使用参考 chunk 并受其正则，critic 学 chunk 的价值。该接口与在 RGB 上独立训练视觉小专家不同。人工纠正属于数据/系统选择，不能把“必须能抢在失败前接管”当作 RLT 的算法定义。[RLT 方法与 Algorithm 1](https://arxiv.org/html/2604.23073v2)

我们可以先不引入 token，但需要承认视觉表示会影响样本效率。以后若比较 token，须把表示和优化算法的变化分开。

### 3.4 EXPO-FT 与实时版本：共同骨架中仍有真正的方法差异

EXPO-FT 同时利用轻量 edit policy、价值选择和 VLA 更新；实时版本进一步区分底座看到的旧观测与编辑器看到的最新观测，并处理 RTC 前缀及备份成本。[EXPO-FT](https://arxiv.org/html/2605.25477v2)、[实时版方法与附录](https://arxiv.org/html/2609.18207v1)

这不只是换任务。它改变可执行决策和 critic 条件。但我们第一阶段冻结 VLA，也不应为了比较而偷偷引入在线底座更新。可先复现冻结条件下最接近的动作编辑基线，并说明与完整算法的差别。

### 3.5 DSRL 与动作残差：两种不同的可探索行为

DSRL 学习如何选初始噪声，使冻结 diffusion/flow 生成器给出更好的动作。动作残差直接改变生成后的命令。前者保留生成先验，后者可在生成结果外作有界修正；哪种更合适取决于底座输出分布与实际失败机制。[DSRL §4](https://arxiv.org/html/2506.15799v2)

若底座已有多种合理接近方式，只是常抽到差的模式，steering 很有吸引力；若始终下降不足，动作残差可能更直接。这是待实验的判断，不能凭直觉宣称 DSRL 做不到。

### 3.6 RECAP：不要再把它等同于人为逐阶段奖励

原文 §V-C 使用 episode 成败标签：非终止步给时间代价，失败终止给较大惩罚，据此学价值并构造优势条件。因此，RECAP 并不要求先为每个任务手工标完所有阶段。任务/子任务语言、数据采集设计与奖励定义也不能混为一谈。[RECAP §V-C，Eq.5](https://arxiv.org/html/2511.14759v1)

我们可以先学外挂专家，同时把 RECAP 留作后训练对照。两者主要区别在策略改进和能力吸收的位置，不是“是否划阶段”这一个维度。

## 4. 两条容易被误当创新的扩展

**交接状态。** Foresight Residual RL 已估计下游成功价值，改善局部成功终态，解决“这个阶段过了，下阶段却接不住”的问题。我们需要借鉴并比较，而不是重新命名。[Foresight Residual RL §IV–V](https://arxiv.org/html/2607.16506v1)

**奖励前提。** ReCoVLA 已通过失败类别和阶段前提选择/激活 reward，减少过早奖励。它主要在仿真中用物体状态训练恢复策略，再进行 sim-to-real；我们的连续真实视觉证据条件有所不同，但简单增加一个 gate 不够构成独立新意。[ReCoVLA §3](https://arxiv.org/html/2606.09630v1)

## 5. 奖励模型是另一个轴，不是另一套必须绑定的 RL 算法

| 方法 | 监督与输出机制 | 对我们有用的部分 | 不能推出的结论 |
|---|---|---|---|
| [RoboReward](https://arxiv.org/html/2601.00675v2) | 跨任务视频奖励数据；负例及 near-miss 增广；VLM 奖励预测 | 短程结果判定对照、负例构造 | 新机器人上不经评估就一定可靠 |
| [Robometer](https://arxiv.org/html/2603.02115v1) | 帧进度与跨轨迹偏好联合监督 | 结果之外的进度/轨迹排序 | 进度相关性高就必然改善我们的 RL |
| [TOPReward](https://arxiv.org/abs/2602.19313) | 从视频 VLM 的回答 token 概率提取进度 | 无任务专用训练的起始基线 | 论文零样本设定等于我们任何任务都无需校准 |
| 当前 DINO/VLM 组合 | 局部参考与序列判断，加规则及助手复核 | 现成开发材料与误判案例 | 已是通过验收的全自动通用奖励模型 |

同一 SAC 专家可以换不同奖励器；同一奖励器也能服务 SAC、数据筛选或后训练。优先把这两个实验轴拆开。必要人工抽检属于测量质量控制，不等于每次 rollout 都由人实时给奖励。

## 6. 算法基础与后续阅读顺序

残差控制、Cal-QL、TD3+BC、Q-chunking 和 delayed-reward RL 都有独立先例。特别是奖励晚到、奖励所属动作不明确，早已有理论研究；“加历史”“用实际 chunk 长度折扣”不能直接叫新方法。[延迟奖励 RL](https://proceedings.mlr.press/v162/han22e.html)、[部分匿名奖励 RL](https://arxiv.org/abs/2305.02527v2)

建议精读顺序：

1. **PLD＋PARTS**：锁定专家、实践、采集、反哺各自做了什么。
2. **RLT＋DSRL＋EXPO-FT/实时版**：比较表示、探索空间和更新位置。
3. **RECAP＋三个奖励模型**：理解如何从好坏经验构造策略信号。
4. **Foresight、ReCoVLA、Q-chunking、延迟奖励**：避免把局部扩展误认成新问题。

现阶段不需要选出“最创新”的方案。先复现可解释基线、记录失败机制，再让实验决定哪些设计值得成为论文主张。候选思路另存 [创新性审计](novelty-audit.md)，不会反过来逼实验给它找证据。
