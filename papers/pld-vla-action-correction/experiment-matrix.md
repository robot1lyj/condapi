# 实验问题与证据矩阵

本文件是待验证的实验设计，不是本轮训练配方。先做最小可解释对照，随后随文献精读与 pilot 调整；不同时启动多套算法。

2026-10-13 补充：项目已开展离线诊断、合成 SAC 验收、真实零修正 probe 和探索包安装，见[最新实验记录](experiments/20261013-rtc-rl/experiment-log.md)。这些结果尚未完成下述独立测试和真机收益实验；本页实验矩阵继续作为研究设计使用。

## 1. 分清四个层级

1. **测量层**：自动奖励是否测到了正确结果，是否属于这次尝试？
2. **学习层**：小专家是否从实际执行的修正中学到了有用决策？
3. **任务层**：局部修正是否提高完整任务表现，还是只是局部指标更好？
4. **吸收层**：关闭专家后，蒸馏过的 VLA 是否仍然更好？

先回答前三级，再做吸收层。不要用某一层成功替代其他层。

## 2. E1：奖励与事件审计

**问题**：现有自动规则、视觉模型与片段边界各自会产生什么错误？

- 当前 14 集用于开发和历史案例；规则冻结后另取新 episode 作为验证与锁定测试。
- 按 episode/采集批次分组，不随机拆帧或拆相邻事件；参考近邻也排除查询 episode 和重复图像。
- 独立人工真值覆盖高低置信度、合格/不合格、成功/失败及未触发片段。审核时尽量隐藏模型条件，保留分歧；不是只挑模型不确定例子。
- 对照固定 ROI/颜色规则、DINO 参考、序列 VLM、现有组合；通用 reward 模型作为可选替换轴。
- 报 held/empty 混淆矩阵、成功误报率、漏报率、证据覆盖率、拒判率和延迟；同时检查检测不到的失败，不只评价闭爪候选。
- 奖励器需要的机时、人工审核分钟、专用阈值和参考样本数也计入。

**反证**：组合模型的收益只来自丢弃大量难例，或固定规则达到同等性能，则不能声称需要更复杂 reward 模型。模型一致率和分类完成率均不能替代这项测试。

## 3. E2：自然错误是否值得成为研究问题

**问题**：归属错误在真实连续 rollout 中是否频繁并影响价值学习？

同一轨迹分开核查：事件身份、物理结果区间、图像采集、reward 返回、控制权、参考与执行命令。统计自然错误，不先人为注入缺陷。

离线比较原记录、只修事件归属、只修执行归属、两者修正及人工 oracle。若天然已经全部对齐，则保留这个结果，不制造坏基线。延迟/歧义注入只作为第二阶段压力测试，单独标明。

**反证**：自然错误罕见，或者普通正确索引解决所有问题，就把对齐定位为工程正确性；研究重心可转向探索、表示或交接，而不是坚持原候选创新。

## 4. E3：最小真机有效性对照

先统一 Pi checkpoint、视觉输入、干预入口、动作允许范围、退出规则、机器人时间和复位预算，再比较：

| 条件 | 配置 | 目的 |
|---|---|---|
| B0 | Pi-only | 可靠基线 |
| B1 | Pi＋合理的确定性局部修正规则 | 区分学习收益与简单工程收益 |
| B2 | Pi＋同容量整段残差 SAC，标准局部 reward，正确记录执行 | 主学习基线 |
| B3 | 与 B2 相同，仅开放夹爪开度修正 | 测整段动作空间是否值得 |
| B4 | 相同干预范围及 reward 的 chunk TD3+BC | 与 PARTS 配方近邻比较，分开算法影响 |
| B5 | 以后确立的候选方法 | 只在明确定义后加入 |

B1 不能只增加抬升高度，然后声称胜过规则修正。B3 若参考 PARTS LEGO，要写清是配置对照；没有复现 selector、reset、重训等整套系统时，不标成“完整 PARTS”。

同样，冻结版 edit policy 与完整 EXPO-FT、独立编码器与 RLT token 不能混称原算法。所有跨论文数字只作背景，不作直接胜负比较。

完整任务主指标用固定预算内最终完成度或成功率，事先选定一个主要终点。LEGO 可把“正确分好数量/起始待分数量”作为主要终点，完整分完率作为另一指标；若要多任务统一比较，应在实验启动前固定每个任务的成功定义与汇总规则。

局部 held、交还成功、后续掉落、重试次数、干预时间和安全停止作为次要指标。所有随机分到该条件的完整 trial 都入分母，包括没闭爪、没抬升、没触发专家和没有合格核验图的 trial。

**反证**：只提高 held，却增加错放、掉落或耗时，不能称完整任务改善。只单个最好种子有收益，也不足以支撑方法可重复性。

## 5. E4：贡献归因与压力测试

固定视觉模型、编码器、SAC 和网络容量，才研究 reward 关联/执行学习规则。候选 2×2 对照：

| | 标准但正确的执行备份 | 以后提出的执行/价值处理机制 |
|---|---|---|
| 标准合格局部 reward | 强基线 | 只变学习规则 |
| 候选证据/归属处理 | 只变奖励处理 | 联合方案 |

没有新的学习规则时，右列不必存在；不能把“错记未执行动作”当标准基线。所有实机组共享正确、安全执行路径。错配消融仅研究数据/学习，不故意让机器人执行错位命令。

进一步分别改变：自然标签返回延迟、事件证据稀疏度、合法 RTC delay/prefix 范围、短时间重试、双臂模式切换。每次只改变一个轴，或在预算允许时设计析因实验。报告精确归属条件下的性能，避免方法只会修人工坏数据。

数据量同时给两种视角：匹配有效样本数量的算法比较，以及相同机器人分钟下的真实利用率。不能让候选方法多用数据后归因为优化器更好。

## 6. E5：通用性分级

| 级别 | 设计 | 允许结论 |
|---|---|---|
| G0 | LEGO 新布局/物体实例 | 同任务分布鲁棒性 |
| G1 | 同框架，抓取＋插入/释放＋关合等不同局部目标，各自训练 | 框架复用性 |
| G2 | 共享模型，目标任务少量适配；与从头专家同预算比较 | 少样本迁移 |
| G3 | 整个任务家族留出，无目标任务调参或训练 | 经过对应测试的零样本泛化 |

起步争取 G1，不预先承诺 G3。跨任务最好包括：重复抓取的跨尝试歧义、遮挡后才能确定的插入/释放、交还后才显现的保持结果。不要把三种颜色算成三个任务家族。

报告每任务新增规则、标签、示例、训练数据与机时。若每任务需要重写大量验收代码，仍可称可适配系统，但应缩小“通用”结论。

## 7. E6：长期保留能力的证据

专家有效后，按相同数据量比较成功 Pi 数据、纯专家数据、PLD 式底座 probing＋专家恢复数据；VLA 原生 SFT 预算相同。关闭专家测原任务、留出场景及原能力保留。

另报专家在线、蒸馏 VLA、原 Pi 三者，不用外挂表现代替蒸馏结果。RECAP 类后训练可成为另一条独立对照，留待资源与证据允许。

**反证**：蒸馏只记住本场景或损害原能力，则“长期能力提升”不成立，即使专家本身有效。

## 8. 数据、统计与预算原则

- **独立单位**：完整 trial 是任务评价单位；episode 是事件/奖励划分及聚类单位；独立训练 run 是学习可重复性的单位；任务家族是泛化单位。
- 327 个候选嵌套在 14 集中，不是 327 次独立机器人试验；连续一小时内多个动作周期也有共享环境和时间相关性。
- 相同预生成起始场景配对比较，时段内随机化方法顺序；记录真实复位偏差。
- 报各 seed、各 task 结果以及方法差值区间。事件诊断按 episode 聚类；任务结果跨 run 分层；不对全部帧做独立伯努利统计。
- pilot 可先考虑 3 个独立 run、至少 2 类局部任务；这是预算建议，不能当功效分析。正式实验根据 baseline、run 间波动、最小实际收益与预算锁定样本量。
- 资源不足时减少条件与主张，不能用一个最好种子的更多评测伪装独立重复。
- 主要终点、排除标准、测试数量与停止规则须在看确证结果前固定。设备故障和策略失败分开；同时报告原始分母与排除数量。
- 奖励版本/规则冻结后再建锁定测试。最终裁判尽量独立于训练奖励器，防止 reward hacking 获得虚假好成绩。
